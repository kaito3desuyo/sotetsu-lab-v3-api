# 目撃の枠割り当て（real-time と過去の運用の推測を 1 つの規則にする）設計

- 日付: 2026-10-19
- ブランチ: API・client とも `fix/carry-return-operation`（このブランチの上に積む）
- 発端: 利用者の報告（2026-10-13）。18K→17K→18K と運番が戻る行程で、過去の運用情報に 3 つ分が出なかった

## 1. 目的

目撃から「その日、どの編成がどの運用を受け持ったか」を推測する規則を、real-time（運用カード・編成カード）と過去の運用情報で 1 つにする。
推測した運用は、どちらの画面でも「?」で示す（@X の添え書き・斜線はやめる）。

## 2. 用語

- **行程**: 車両 1 台がたどる 1 日の区間の連なり（`VehicleItinerary`。既存）
- **枠**: 行程を運番が切り替わるところで区切ったまとまり（`VehicleItinerary.runs()`。このブランチで追加済み）。18K→17K→18K なら 3 枠
- **実目撃**: その枠に結び付いた、無効化されていない直接の目撃
- **推測**: 実目撃の無い枠に、同じ行程のほかの枠の実目撃から編成を割り当てたもの

## 3. 規則

### 3.1 目撃を枠に結び付ける

目撃の運番と時刻から、その運番の区間を「受け持ち中（[start, end)）→ 次に始まる → 直前に終わった」の順に選び、その区間の枠に結び付ける。
先回りの入力（X を走っている最中に、次に受け持つ Y と入れる）を、次の Y に付けるため。

- 検索時刻から運用の今の区間を選ぶ口（`segmentOfOperationAt`。受け持ち中 → 直前に終わった → 最初）は変えない。目撃用の口を別に作る
- 時刻表に枠の無い運番の目撃（休車 100・時刻表に無い運番）は、どの枠にも結び付かない

### 3.2 枠に編成を割り当てる

使う目撃は、その鉄道日（4:00 区切り）の有効な目撃。real-time は検索時刻まで、過去の運用はその日の全部。過去の運用で無効化も表示するときは、無効化された目撃も含める（7 章）。

1. その枠に実目撃があれば、その編成（実目撃）。複数の編成なら一番新しい目撃の編成（併結は無い。入力の食い違い）
   - 目撃の新旧は「目撃時刻 → 投稿時刻（あとから投稿したほうを訂正とみなして新しい扱い）→ id」で決める。同じ時刻でも入力の並びで答えが揺れないようにする。推測の元・候補どうし・推測に載せる目撃の比べ方も同じ
2. 無ければ推測。候補は、同じ行程のほかの枠に実目撃がある編成。ただし次の編成は外す
   - その編成が、「枠」と「元の実目撃」の間の時間帯（両端を含む）に、別の行程の目撃・枠に結び付かない目撃（休車 100 など）を持つ
3. 候補が複数なら、枠の始まりまでに実目撃された中で一番遅い編成（前から続く側）。いなければ、一番早く実目撃された編成
4. 候補がいなければ割り当て無し

### 3.3 real-time の運用カード

1. その運番の今の枠を、検索時刻で選ぶ（受け持ち中 → 直前に終わった → 最初。既存の `itineraryOfOperationAt` のまま）
2. その枠の割り当てを出す
   - 実目撃 → 「編成」
   - 推測 → 「編成?」（前日からの順送りと同じ見せ方）。`latestSighting` はその運番自身の最後の目撃で、太字・下線と目撃・更新の時刻の色はそれで決まる（17K の目撃から推した 18K? を、17K の目撃で太字・赤字にしない）
   - 割り当て無しで、その行程に今日の実目撃が 1 件以上ある → 不明
   - その行程に今日の実目撃が 1 件も無い → 今と同じ扱い。その運番の今日の目撃が別の行程にあれば不明（朝の 02K の編成を夕方の 02K に出さない）、無ければ前日からの順送り

### 3.4 real-time の編成カード

1. その編成の今日の実目撃のうち一番新しいものの行程を、その編成の行程とする。今日の実目撃が無ければ今の判定（順送り）へ落とす
2. その行程の今の枠を、検索時刻で選ぶ（受け持ち中 → 直前に終わった → 最初）
3. その枠の割り当てで出す
   - この編成の実目撃 → 「運番」
   - この編成の推測 → 「運番?」
   - ほかの編成に割り当てられている → 不明
   - 割り当て無し → 不明
4. 一番新しい目撃が枠に結び付かない（休車 100 など）ときは、今の判定のまま（100 なら「休」）

行程がその日の最後まで行き、ほかの編成に取られずに終わったときは、2 の「直前に終わった」で最後の枠が選ばれ、最後の運用を出し続ける（今と同じ）。

### 3.5 過去の運用情報

- 実目撃は今までどおり 1 件ずつタグで出す（同じ枠に複数あれば複数。無効化も表示のときは赤枠）
- 推測の枠は、その編成の行に「運番?」のタグで出す。推測の元の運番はタグの title にだけ残す
- 並びは、同じ行程の中では枠の受け持つ順。行程が分からない目撃は目撃時刻（このブランチで実装済み）
  - 行程をまたぐときは、その編成がその行程に入った時刻の順（キーは [行程に入った時刻, 枠の始まり]）。同じ行程に 2 回入ったら（I → J → I）、訪問ごとに別に並べる
- 不明は出さない（受け持った運用だけを並べる）

### 3.6 鉄道日

推測は 1 鉄道日の中だけで行う。翌朝の出庫とのつながりは、今の前日からの順送り（運用番号の循環）に任せる。

## 5. API の変更

- `vehicle-itinerary.read-model.ts`: 目撃用の区間の選び方（3.1）を足す
- `sighting-carry-over.read-model.ts`: 枠の割り当て（3.2）を 1 か所で作る。`resolveForOperation`（3.3）・`resolveForFormation`（3.4）・`buildCarried`（3.5）はその結果を引くだけにする
  - 戻り値の約束は今と同じ: undefined＝行程表で判定できない（今の判定へ落とす）、null＝不明
- `sightedAsOperation` は「推測した割り当て」の目印として残す（推測なら推測の元の目撃の運番、実目撃なら null）。real-time・過去の運用とも同じ
- `operation-sighting.v3.service.ts` の時刻断面 2 つは、上の戻り値をそのまま使う。前日からの順送りの経路は変えない

## 6. client の変更

- real-time の運用カード: `sightedAsOperation` があれば編成番号の後ろに「?」を付ける（順送りと同じ）。@X は出さない
- real-time の編成カード: `sightedAsOperation` があれば運番の後ろに「?」を付ける。@X は出さない
- 過去の運用情報: 斜線（`hatched`）をやめ、`sightedAsOperation` があればタグの運番の後ろに「?」を付ける。`operation-number-tag` の `hatched` 入力は消す

## 7. 決めたこと（2026-10-15〜19、ユーザー判断）

- 推測は「?」。@ と斜線はやめる（斜線は一度入れて撤回）
- 取り合いの枠は前から続く側に付ける（朝 3122・夕方 3113 なら間の 17K は 3122）
- ほかの編成に取られた後の編成カードは不明（切替③の「不明にはしない」は撤回）
- 戻り②の運用カード Y は A?
- 併結は無い
- 推測できない枠（行程に今日の実目撃あり）は不明。順送りに戻さない
- 休車 100 は「別の場所にいた証拠」として扱う
- 推測は 1 鉄道日の中だけ
- 同じ時刻の目撃は投稿の新しいほう、それも同じなら id で決める（2026-10-19）
- 先回りの入力で運用カードが「?」になる時間帯（終わった枠を選ぶため）はそのままにする。先回りは勧めたくないので、確定に見せない（2026-10-19）
- 時刻表どおりに走らない日は、実目撃が入った以降の枠が新しい編成で推測される今の規則のままにする（2026-10-19）
- 無効化された目撃は「その記録が誤り」という意味で、編成がその枠にいなかった証拠には使わない（2026-10-19）
- 過去の運用で無効化も表示するときは、無効化された目撃も実目撃と同じく枠に置いて流れを組む。real-time と、無効化を表示しない過去の運用は有効な目撃だけ。推測のタグに写す目撃は有効なものを優先し、無効化された目撃だけが根拠のときに限り赤枠の「?」になる（2026-10-19）
- real-time の運用カードで推測の行の太字・時刻の色は、その運番自身の最後の目撃で決める（推測の元になった別の運番の目撃では決めない）（2026-10-19）
- 画面の言葉: 同じ日に編成が別の運番へ移るのを推すことは「同日引き継ぎ」と呼ぶ（前日からの「順送り」と対）。凡例は「順送り・同日引き継ぎで推測した編成・運用番号」。「車両のつながり」は分かりにくいので画面には出さない（2026-10-19）

## 8. テスト
